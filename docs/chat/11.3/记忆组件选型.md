# 记忆组件选型决策

- 日期：2026-11-03
- 状态：已决定，待落地
- 涉及文件：`app/agent/main.py`（Agent 服务入口）
- 运行环境：Python 3.14 / `agentscope[service,storage-redis]==2.0.11`

## 一、决策摘要

Agent 服务接入 **ReMe 长期记忆**（`agentscope.middleware.ReMeMiddleware`），采用：

| 决策项 | 取值 |
|---|---|
| 记忆后端 | ReMe，进程内嵌（`reme-ai`），不单独起服务 |
| 隔离维度 | **一个学生一个 vault**：`<data_root>/memory/reme/<user_id>` |
| 检索模式 | `agent_control`（只暴露 `memory_search` 工具，不做自动检索注入） |
| 向量检索 | **启用**（DashScope `text-embedding-v4`，1024 维） |
| 写回 | 自动（ReMe 的 `auto_memory`，所有 mode 都跑） |
| 中间件实例 | 按 `user_id` 缓存复用，**禁止每轮新建** |
| 工具面 | 摘掉 `Bash/PowerShell/Edit/Glob/Grep/Read/Write`，只留记忆与业务工具 |

## 二、背景

当前 `app/agent/main.py` 用 AgentScope 服务层 `create_app()` 起服务，Agent 在每轮对话时按 session 动态装配。现状是：

- **会话内短期记忆已内置**：`SessionRecord.state`（`AgentState.context`）随会话存入 Redis DB1，`chat_config.context_config` 负责超长时压缩。
- **跨会话长期记忆缺失**：学生换个会话，Agent 就完全不认识他了。

教学场景需要长期记住的是：学生画像（班级、进度）、薄弱知识点、讲解偏好、老师/学生的明确叮嘱。

## 三、约束（来自需求方）

1. Agent 需要**工具调用**能力。
2. **不需要 shell 执行**能力。
3. **不需要写记忆以外的文件**。
4. **低成本**。
5. **快速启动**。

## 四、候选方案与排除理由

| 方案 | 结论 | 理由 |
|---|---|---|
| Mem0 云服务 | 排除 | 见下 |
| AgenticMemory（文件型） | 排除 | 见下 |
| **ReMe（进程内嵌）** | **采用** | 唯一满足"不给 agent 文件工具"的方案 |

### 4.1 为什么排除 Mem0 云服务

| 维度 | 实测/查证结果 |
|---|---|
| 计费 | 免费档 1,000 次检索/月；Starter $19 = 5,000 次；Pro $249 = 50,000 次 |
| 用量 | `mode="both"` 下**每轮回复前同步检索一次**，40 人班 × 4 轮/天 ≈ 4,800 次/月，Starter 仅够一个班 |
| 延迟 | 直连 `api.mem0.ai` 实测 TTFB 0.4–0.9s，且检索在生成首字之前的同步链路上 |
| 合规 | 学生画像与对话原文出境至第三方，教育/未成年人信息在 PIPL 下需要单独同意与出境评估 |
| 可维护性 | 记忆在对方库中：老师端不可见、错误记忆改不掉、中文抽取 prompt 不可调 |
| 依赖副作用 | `agentscope[memory-mem0]` 会把 `protobuf` 从 7.36 降到 6.33，影响现有 COS SDK 需另行验证 |

### 4.2 为什么排除 AgenticMemory

`AgenticMemoryMiddleware` 成本最低、零新增依赖、数据本地可读可改，本身是很好的方案，但它的工作机制是**让模型用 `Write`/`Read` 工具自行维护 `Memory/*.md`**。

这与"不需要写记忆以外的文件"的约束冲突：一旦保留 `Write` 工具，就无法从工具层面限制模型只写记忆目录。若未来要收紧权限，需要额外做路径级权限控制。

结论：作为备选方案保留，若 ReMe 的抽取质量或成本不可接受，可回退到此方案（届时需接受 `Write`/`Read` 常驻）。

### 4.3 为什么选 ReMe

- **写回自动**：ReMe 通过 `on_reply` 钩子监听对话，回复结束后由 `auto_memory` 任务写回记忆卡片，agent 自身**不需要**任何文件工具。
- **工具面极简**：`agent_control` 模式下只暴露一个 `memory_search`，没有 `add_memory`（对比 Mem0 有 add/search 两个）。
- **本地可读**：vault 是本地 Markdown 卡片 + 本地索引；记忆本体不出本地，只有 embedding 计算调用 DashScope（境内）。
- **可观测**：记忆卡片是文件，可直接查看、grep、人工修正、按学生删除。

## 五、关键设计决策

### 5.1 workspace 选择

ReMe 的 `workspace_dir` 是它自己的 vault（daily 卡片、digest、关键词/向量索引），**不是** agent 的工作区。

两个关键语义：

- **写入**按 `session_id` 落卡片，`session_id` 由中间件从 `agent.state.session_id` 实时读取，无需配置。
- **检索**扫的是**整个 workspace**，不按 session、不按 user 过滤。

因此**用户隔离只能靠目录**。备选位置对比：

| 位置 | 隔离粒度 | 生命周期 | 结论 |
|---|---|---|---|
| `<data_root>/memory/reme/<user_id>` | 按学生 | 独立于 agent/workspace | **采用** |
| `<workspace.workdir>/.reme` | 按 agent | 跟随 workspace TTL，容器化后丢失 | 拒绝 |
| 全局单一 `.reme` | 无 | 全局 | 拒绝（学生会检索到彼此的记忆） |

### 5.2 检索模式：`agent_control`

| mode | 行为 | 每轮成本 |
|---|---|---|
| `static_control` | 自动检索并在推理中注入，不暴露工具 | 1 次检索调用 |
| `agent_control` | 只暴露 `memory_search`，由模型按需调用 | 仅模型主动调用时产生 |
| `both` | 自动检索 + 暴露工具 | 最高 |

选 `agent_control`：满足"需要工具调用"的约束，同时把检索从每轮固定开销变成按需开销。

### 5.3 启用向量检索

> 本节已按最新决策调整：早期方案为"仅 bm25"，实测"同义表述召回不到"后改为启用 embedding。

传 `embedding_model`（DashScope `text-embedding-v4`，1024 维）后，ReMe 的检索是关键词 + 向量的混合模式（`vector_weight=0.7`）。

- 成本：写入与检索各一次 embedding，按 token 计，远低于对话模型；
- 收益：实测「这门课我哪个部分学得最差」能召回「网络层最弱、子网划分」的卡片，纯关键词做不到；
- 代价：多一个外部依赖（DashScope 原生接口），启动时多初始化一个 embedding 组件。

### 5.4 实例必须缓存

`create_app(extra_agent_middlewares=...)` 的工厂**每轮对话调用一次**。而 ReMe 中间件在首次使用时 `_build_app()` + `start()`，内部会启动：

- 一个常驻的 `index_update_loop` 文件监听（watch `daily_dir` / `digest_dir`）
- 一个 `0 23 * * *` 的 `dream_cron` 记忆归并任务

中间件**没有框架托管的生命周期**，需要显式 `close()`。因此每轮新建实例会持续泄漏后台任务。

→ 必须按 `user_id` 缓存中间件实例，进程内复用。

## 六、落地代码（建议放在 `app/agent/memory.py`）

```python
from pathlib import Path

from agentscope.agent import Agent
from agentscope.credential import OpenAICredential
from agentscope.middleware import MiddlewareBase, ReMeMiddleware
from agentscope.model import OpenAIChatModel

from app.core.config import get_settings

# 服务层默认下发 6 个内置工具 (Bash/Edit/Glob/Grep/Read/Write)，没有开关
_STRIP_TOOLS = ["Bash", "PowerShell", "Edit", "Glob", "Grep", "Read", "Write"]


class MemoryOnlyToolsMiddleware(MiddlewareBase):
    """每轮回复前摘掉 shell 与文件工具，只保留记忆与业务工具。"""

    async def on_reply(self, agent: Agent, input_kwargs: dict, next_handler):
        await agent.toolkit.remove_tool(_STRIP_TOOLS)
        async for item in next_handler(**input_kwargs):
            yield item


_REME_CACHE: dict[str, ReMeMiddleware] = {}


def _reme_model() -> OpenAIChatModel:
    settings = get_settings()
    return OpenAIChatModel(
        credential=OpenAICredential(
            api_key=settings.llm.api_key,
            base_url=settings.llm.base_url,
        ),
        model=settings.llm.model,
    )


async def memory_middlewares(
    user_id: str,
    agent_id: str,
    session_id: str,
    workspace,
) -> list[MiddlewareBase]:
    """按学生装配长期记忆：一人一个 vault，实例缓存复用。"""
    mw = _REME_CACHE.get(user_id)
    if mw is None:
        mw = ReMeMiddleware(
            workspace_dir=str(
                Path(get_settings().data_root) / "memory" / "reme" / user_id
            ),
            parameters=ReMeMiddleware.Parameters(
                chat_model=_reme_model(),
                mode="agent_control",
                top_k=5,
            ),
        )
        _REME_CACHE[user_id] = mw
    return [mw, MemoryOnlyToolsMiddleware()]
```

`app/agent/main.py` 增加一行：

```python
from app.agent.memory import memory_middlewares

return create_app(
    ...,
    extra_agent_middlewares=memory_middlewares,
)
```

## 七、依赖与配置变更

```bash
uv add "agentscope[memory-reme]==2.0.11"
```

- 实测该 extra 在 Python 3.14 下可解析：共 28 个包（含 `fastmcp`、`loguru`、`authlib`），**无 protobuf 降级冲突**。
- **`reme-ai` 必须钉 `0.4.1.11`**：`>=0.4.1.12` 移除了 `dream_topics_step`，而 AgentScope 2.0.11 的内嵌配置仍引用它，装最新版会在启动时抛 `Unregistered backend 'dream_topics_step'`。
- 复用现有 `LLM_*` 配置（OpenAI 兼容端点 + `qwen3.8-flash`），不新增环境变量。
- 新增数据目录：`<data_root>/memory/reme/<user_id>/`，需纳入备份与数据清理流程。

## 八、风险与未决项

| # | 风险 | 说明 | 处理 |
|---|---|---|---|
| 1 | 实例缓存无界 | `_REME_CACHE` 只增不减，每学生对应一个文件监听 + 一个 23:00 cron | 规模化前加 LRU 上限与空闲回收 |
| 2 | 无优雅关闭 | 中间件不由框架托管，进程退出时内嵌 app 不会 `close()` | 在 lifespan 中补充清理 |
| 3 | 水平扩展不成立 | vault 与索引是**进程内 + 本地文件**，多 worker / 多副本下每个进程各一份监听与索引 | 单实例部署；多副本前需改为共享存储或换方案 |
| 4 | 每轮抽取成本 | `auto_memory` 每次回复后跑一次抽取（内部为 AgentScope agent，`max_iters=30`） | 上线后实测 token 与耗时，必要时降低触发频率 |
| 5 | dream 集中触发 | 每个 vault 一个 `0 23 * * *` 归并任务，学生多时同一分钟集中跑 | 控制在可接受规模，或改为离线批处理 |
| 6 | 用户身份来源 | `user_id` 取自请求头 `X-User-ID`（`agentscope.app.deps.get_current_user_id`），缺失直接 401 | 网关必须逐学生透传真实 ID，否则记忆会串 |
| 7 | 运行时未验证 | 目前只做了依赖解析（dry-run），未实际跑通 `reme-ai` | 落地后跑一次端到端：首轮写入 → 新会话检索 → 查看卡片文件 |
| 8 | 数据合规 | vault 内含学生画像与对话摘要 | 提供按学生导出/删除能力 |

## 九、验收标准

1. 学生 A 首轮对话后，`<data_root>/memory/reme/<A>/` 下出现记忆卡片文件。
2. 学生 A 新开一个会话，问及此前信息时，Agent 能调用 `memory_search` 并答对。
3. 学生 B 的 vault 目录独立，B 的检索结果中不出现 A 的内容。
4. 学生侧工具列表中没有 `Bash`/`Write`/`Read`，只有 `memory_search` 与业务工具。
5. 同一学生连续 10 轮对话，进程内活跃的 ReMe 实例数恒为 1。
6. 服务重启后，历史记忆仍可检索（vault 落在磁盘，不依赖内存状态）。
