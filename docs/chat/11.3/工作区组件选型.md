# 工作区（Workspace）组件选型决策

- 日期：2026-11-03
- 状态：已决定，待落地
- 涉及文件：`app/agent/main.py`（Agent 服务入口）、`app/agent/memory.py`（每轮装配中间件的工厂）
- 运行环境：Python 3.14 / `agentscope[service,storage-redis]==2.0.11`

## 一、决策摘要

工作区使用**框架内置的本地目录实现**，不引入任何容器或云沙箱：

| 决策项 | 取值 |
|---|---|
| 实现 | `LocalWorkspaceManager`（`agentscope.app.workspace_manager`） |
| 目录布局 | `<data_root>/workspaces/<agent_id>/` |
| 隔离粒度 | `IsolationPolicy.PER_AGENT`（默认值） |
| 缓存 TTL | 3600 秒，**懒驱逐**（无后台清扫任务） |
| 预构建 | 不启用（`LocalWorkspaceManager` 本身不支持 `PrewarmConfig`） |
| 系统提示 | **覆写**为教学精简版（默认文案描述的是开发者工作区，见 5.3） |
| 提供的工具 | 全部剔除（`Bash/Edit/Glob/Grep/Read/Write`），见记忆方案 |
| 外部依赖 | 无（不需要 Docker、不需要 API Key、不需要集群） |
| 新增数据目录 | `<data_root>/workspaces/` |

一句话：**本地目录 + 每 agent 一个 workdir + 覆写系统提示 + 不向学生暴露 `/workspace` 文件路由。**

## 二、背景

`create_app()` 的 `workspace_manager` 是**必填参数**——每一轮对话和所有 `/workspace` 路由都依赖它，无法像 `knowledge_base_manager` 那样传 `None` 关闭。

Workspace 在 AgentScope 服务层里承担五件事：

| 职责 | 用途 | 本项目是否需要 |
|---|---|---|
| `list_tools()` | 下发 6 个内置工具（Bash/Edit/Glob/Grep/Read/Write） | **不需要**，见记忆方案已剔除 |
| `offloader` | 工具结果超限时落盘到 `sessions/<session_id>/tool_result-*.txt` | 需要（兜底） |
| `skills` | 技能目录的分区与索引 | 暂不需要 |
| `mcp` | 每个 agent/session 的 MCP 声明 | 暂不需要 |
| `get_instructions()` | 把工作区说明追加进系统提示 | **必须改写**，见 5.3 |

`app/agent/main.py` 现在已经在用 `LocalWorkspaceManager(str(settings.workspaces_dir))`，本文档是把"为什么是它、还要改什么"固化下来。

## 三、约束

1. 单机部署，尽量少加常驻服务（现有 PG + Redis 两个容器）。
2. **快速启动**：学生点开学就能聊，不能等镜像拉取或容器构建。
3. **低成本**：不新增云资源、不按秒计费。
4. Agent 不给 shell、不给文件读写工具（记忆方案已定）。
5. 学生之间互不可见。
6. 复用现有 `<data_root>` 持久目录。

## 四、候选方案与排除理由

AgentScope 2.0.11 内置 8 种 workspace manager：

| 方案 | 启动成本 | 外部依赖 | 隔离强度 | 结论 |
|---|---|---|---|---|
| **LocalWorkspaceManager** | **实测初始化 ~22ms** | 无 | 无（同进程、同宿主机） | **采用** |
| DockerWorkspaceManager | 镜像构建 + 容器启动，秒级~分钟级 | Docker 守护进程 | 容器级 | 排除 |
| BubblewrapWorkspaceManager | 进程级沙箱，较快 | `bwrap`，**仅 Linux** | 文件系统/命名空间 | 排除 |
| AppleContainerWorkspaceManager | 拉取 OCI 镜像 | macOS + `container` 运行时 | 容器级 | 排除 |
| E2BWorkspaceManager | 远程创建沙箱，秒级 | E2B API Key，数据出境 | 云沙箱 | 排除 |
| DaytonaWorkspaceManager | 远程创建沙箱 | Daytona API Key，数据出境 | 云沙箱 | 排除 |
| K8sWorkspaceManager | Pod + PVC 调度 | K8s 集群 | Pod 级 | 排除 |
| OpenSandboxWorkspaceManager | 远程创建沙箱 | 自建/云 OpenSandbox 服务 | 云沙箱 | 排除 |

排除理由补充：

- **Docker**：本机虽有 Docker 29.8.1，但每个 workspace 是一个常驻容器（`as_ws_<id>`），冷启动要生成 Dockerfile、构建镜像、装 `extra_pip`；同时 manager 会额外起一个后台清扫任务（`sweep_interval=300`）。对一个"只聊天、不执行代码"的 agent 来说，付出的是内存和启动时间，换来的是用不上的隔离。
- **Bubblewrap**：开发机是 macOS，`bwrap` 不存在（实测 `bwrap not found`）；生产若是 Linux 才可用，且同样带后台清扫任务。
- **AppleContainer**：只能跑在 macOS，生产环境是 Linux，不可选。
- **E2B / Daytona / OpenSandbox**：按秒计费 + 需要 API Key + 学生对话数据出境，与知识库方案里"不外传原始文件"的约束冲突。
- **K8s**：需要集群，远超当前单机规模。

## 五、关键设计决策

### 5.1 为什么本地目录够用

我们已经在 `MemoryOnlyToolsMiddleware` 里剔除了全部文件与 shell 工具。剔除之后，本地文件系统的暴露面只剩两条：

1. **offloader 写入**：框架行为，路径固定在 `<workdir>/sessions/<session_id>/`。
2. **`/workspace` REST 路由**：这是真正的风险点，见 5.4。

没有代码执行能力，就没有必须靠容器隔离的威胁模型。反过来说：**一旦将来恢复 `Bash` 工具，必须立刻切到 Docker**——`LocalWorkspace` 的 `Bash` 直接跑在宿主机上（`cwd=workdir`，无命名空间隔离）。

### 5.2 隔离粒度选 `PER_AGENT`

三种粒度的行为差异（`WorkspaceManagerBase.assign_workspace_id`）：

| 粒度 | workspace id 生成 | 本项目评价 |
|---|---|---|
| `PER_SESSION` | 每次会话新 UUID | 每次会话新目录，`sessions/` 上下文不连续，目录数随会话爆炸 |
| `PER_AGENT`（默认） | 绑定到 `(user, agent)` 首个会话 | **采用**：一个学生一个 agent 一个目录，稳定 |
| `PER_USER` | `blake2b(user)` | 不采用 |

`PER_USER` 不采用的原因：`LocalWorkspaceManager.get_workspace()` 的 workdir **始终**按 `agent_id` 拼接（`os.path.join(basedir, agent_id)`），而缓存键是 `workspace_id`。选 `PER_USER` 时，同一学生的第二个 agent 会命中第一个 agent 的缓存条目，拿到**别人（其实是同一个人的另一个 agent）的 workdir**——行为不直观，容易埋坑。

目录布局：

```
<data_root>/workspaces/<agent_id>/
├── sessions/     # 工具结果、会话上下文落盘（系统维护）
├── skills/       # 技能分区（当前未启用）
└── data/         # 多模态文件（当前未启用）
```

注意与 Docker 实现的差异：Docker 是 `<basedir>/<user_id>/<agent_id>` 两级，Local 只有一级 `<basedir>/<agent_id>`。agent_id 是 UUID，不会冲突。

### 5.3 必须覆写 `instructions`（容易漏掉的一步）

`LocalWorkspace` 的默认 `instructions` 是一段**面向开发者 agent** 的长提示（约 1.5k 字符），内容包括：

- "你有 Bash、git、uv，按任务建子目录"
- "每个项目要建 `README.md`、初始化 git 仓库"
- "用 `git worktree` 避免多会话冲突"

而 `Agent._get_system_prompt()` 会**无条件**把 `offloader.get_instructions()` 追加进系统提示（`agentscope/agent/_agent.py`）：

```python
if isinstance(self.offloader, WorkspaceBase):
    offload_instructions = await self.offloader.get_instructions()
    if offload_instructions:
        prompt.append(offload_instructions)
```

本项目 `offloader=workspace`，所以这段文案每轮都会进上下文。工具已经剔光，却还在教模型"用 Bash 建 git 仓库"，后果是模型持续尝试调用不存在的工具、或把记忆写进不存在的目录。

**处理方式**：`LocalWorkspaceManager` 没有暴露 `instructions` 参数，但 `extra_agent_middlewares` 工厂能拿到 `workspace` 对象，且工厂在 agent 构造**之前**调用（`_chat.py` 中工厂在装配阶段执行，agent 在稍后创建），因此直接改公开属性即可：

```python
TEACHING_WORKSPACE_INSTRUCTIONS = (
    "<workspace>\n"
    "你拥有一个属于当前学生的工作目录, 由系统自动维护。\n"
    "你不直接读写其中的文件, 也不需要创建目录或项目。\n"
    "</workspace>"
)

async def agent_middlewares(user_id, agent_id, session_id, workspace):
    workspace.instructions = TEACHING_WORKSPACE_INSTRUCTIONS
    ...  # 记忆中间件 + 工具裁剪
```

> 注意：`instructions` 只在 `LocalWorkspace.__init__` 里做过一次 `{workdir}` / `{backend}` 格式化，构造后再赋值不会格式化。因此自定义文案里**不要写占位符**，需要路径就自己 `f-string` 拼。

### 5.4 安全：`/workspace` 文件路由必须挡掉

这是选 `Local` 唯一的硬风险。`agentscope/app/_router/_workspace.py` 的注释写得很直白：

> Paths are not confined to the workspace root: for a sandboxed backend the reachable filesystem is the sandbox, and for a local one **the caller is already trusted with the host**.

实际代码：

```python
target = backend.abspath(path, cwd=workspace.workdir)
```

而 `BackendBase.abspath()` 对绝对路径直接 `normpath` 返回，不做收敛。结果是：

| 路由 | 行为 |
|---|---|
| `GET /workspace/directories?agent_id&session_id&path=/` | 列宿主机任意目录 |
| `GET /workspace/files?agent_id&session_id&path=/etc/passwd` | **流式返回宿主机任意文件** |
| `POST /workspace/files/download-token` | 为任意路径签发下载令牌 |

身份只靠 `X-User-ID` 明文头（`agentscope.app.deps.get_current_user_id`）。只要主 API 原样转发这两条路由，**任何登录学生都能读到 `app/.env`（LLM key、DB 密码、JWT secret）、其他学生的 workspace、Redis 落盘文件**。

**处理方式（二选一，推荐都做）**：

1. 主 API 白名单代理：只转发 `/chat`、`/session`、`/agent`、`/knowledge_bases` 等业务路由，**不转发 `/workspace/*`**。
2. 若确需文件上传/浏览，在代理层做路径收敛校验（`realpath` 必须落在该用户的 `<workdir>` 前缀内），或改为独立的上传接口写自己的对象存储。

另外 `create_app()` 未传 `download_secret`，框架会每个进程随机生成一个（`secrets.token_urlsafe(32)`）：下载令牌重启后全部失效，多进程之间也互不通用——这又是一条"必须单进程部署"的理由。

### 5.5 与 offloader 的关系（剔除 `Read` 的副作用）

`agent = Agent(..., offloader=workspace)`，当某个工具结果超过 `ContextConfig.tool_result_limit`（默认 50,000）时，框架会把完整结果写到 `<workdir>/sessions/<session_id>/tool_result-<id>.txt`，并在上下文里留一个指针，提示模型"用 `Read` 工具读这个文件"。

我们已经把 `Read` 剔除了 → **这条兜底链是断的**。

结论：

- 业务工具（题目查询、记忆检索等）必须控制返回体量，单次结果建议 **< 20k 字符**；
- 如果将来出现大结果场景（例如整章讲义），要么保留 `Read`（代价：`Read` 在 Local backend 下同样能读宿主机任意绝对路径），要么改成工具侧分页返回。

## 六、落地代码

### 6.1 入口（`app/agent/main.py`）

保持不变，只把语义写明确：

```python
workspace_manager=LocalWorkspaceManager(
    str(settings.workspaces_dir),
    isolation=IsolationPolicy.PER_AGENT,  # 默认值, 写出来是为了防止被误改
    ttl=3600.0,
),
```

### 6.2 每轮装配（`app/agent/memory.py`，建议改名为 `app/agent/middlewares.py`）

```python
from agentscope.agent import Agent
from agentscope.middleware import MiddlewareBase, ReMeMiddleware

from app.core.config import get_settings

TEACHING_WORKSPACE_INSTRUCTIONS = (
    "<workspace>\n"
    "你拥有一个属于当前学生的工作目录, 由系统自动维护。\n"
    "你不直接读写其中的文件, 也不需要创建目录或项目。\n"
    "</workspace>"
)

_STRIP_TOOLS = ["Bash", "PowerShell", "Edit", "Glob", "Grep", "Read", "Write"]


class MemoryOnlyToolsMiddleware(MiddlewareBase):
    """每轮回复前摘掉 shell 与文件工具。"""

    async def on_reply(self, agent: Agent, input_kwargs: dict, next_handler):
        await agent.toolkit.remove_tool(_STRIP_TOOLS)
        async for item in next_handler(**input_kwargs):
            yield item


async def agent_middlewares(user_id, agent_id, session_id, workspace):
    # 工厂在 agent 构造之前执行, 此时改写会生效
    workspace.instructions = TEACHING_WORKSPACE_INSTRUCTIONS
    return [await get_reme(user_id), MemoryOnlyToolsMiddleware()]
```

## 七、依赖与配置变更

- **新增依赖：无**。`LocalWorkspaceManager` 属于 `agentscope[service]`，现有环境即可。
- 复用现有 `DATA_ROOT`，无需新增环境变量。
- 新增/沿用数据目录 `<data_root>/workspaces/`，需纳入备份与磁盘清理。
  - 该目录只存会话级中间产物（工具结果落盘、多模态缓存），**不是**记忆（记忆在 `<data_root>/memory/reme/<user_id>`）也不是知识库原件（在 `<data_root>/blobs`）。

## 八、风险与未决项

| # | 风险 | 说明 | 处理 |
|---|---|---|---|
| 1 | `/workspace` 路由任意路径读取 | 路由不做路径收敛，Local 后端读到的是宿主机 | 主 API 不转发 `/workspace/*`；见 5.4 |
| 2 | 恢复文件/shell 工具即失去隔离 | Local 的 `Bash` 直接跑在宿主机 | 一旦恢复工具，立刻切 `DockerWorkspaceManager` |
| 3 | offloader 兜底失效 | 已剔除 `Read`，超限结果无法回读 | 业务工具单次结果控制在 20k 以内 |
| 4 | 覆写 `instructions` 依赖时序 | 依赖"工厂先于 agent 构造"这一实现细节 | 升级 AgentScope 时复核 `_chat.py` 的装配顺序 |
| 5 | 单进程约束 | workspace 缓存与 `download_secret` 都是进程内状态 | 部署固定单 worker；扩展前改 Docker/共享存储 |
| 6 | 多 worker 并发写同一目录 | 磁盘目录共享，缓存不共享，可能同时写 `sessions/` | 同上，先固定单 worker |
| 7 | 磁盘只增不减 | TTL 只驱逐内存缓存，不删磁盘文件 | 定期清理 `workspaces/`；按 agent 删除 |
| 8 | agent 删除后目录残留 | 框架不联动清理 | 业务侧删除 agent 时一并清理目录 |
| 9 | Docker 方案未实测 | 本文档未对 Docker 做启动耗时基准 | 切换前先跑基准与镜像缓存策略 |

## 九、验收标准

1. 新会话首轮对话，workspace 初始化耗时 < 100ms（本地实测约 22ms）。
2. `<data_root>/workspaces/<agent_id>/` 下存在 `sessions/` 等目录；同一 agent 的后续会话复用同一目录。
3. 学生 A 与 B 的 agent 目录不同。
4. 系统提示中**不含** Bash / git / uv / README 相关内容（覆写生效）。
5. 学生侧工具列表中没有 `Bash`/`Write`/`Read`/`Edit`/`Glob`/`Grep`。
6. 通过主 API 请求 `/workspace/files?path=/etc/passwd` 返回 403/404（路由未转发）。
7. 服务重启后，同一 agent 的目录与历史落盘文件仍在，不被重建。

| 结论 | 依据 |
|---|---|
| `workspace_manager` 是 `create_app` 必填参数 | `agentscope/app/_app.py::create_app` 参数与 docstring（"Required"） |
| Workspace 承担工具、offloader、skills、MCP、系统提示五类职责 | `agentscope/workspace/_base.py` 的 `list_tools` / `get_instructions` 等接口 |

| Docker 目录是两层 `<user>/<agent>` | 同上（"Workdir layout is two levels"） |
| Local 的 workdir 恒按 `agent_id` 拼 | `_local_workspace_manager.py` 中 `os.path.join(self._basedir, agent_id)` |
| `PER_USER` 会命中同一缓存条目 | 缓存键为 `workspace_id`，`assign_workspace_id` 在 `PER_USER` 下是 `blake2b(user)` |
| 默认 `instructions` 是开发者工作区文案 | `agentscope/workspace/_local_workspace.py::LocalWorkspace.__init__` 的 `instructions` 默认值 |
| `instructions` 被无条件追加进系统提示 | `agentscope/agent/_agent.py::_get_system_prompt` 中 `isinstance(self.offloader, WorkspaceBase)` 分支 |
| 工厂在 agent 构造之前执行 | `agentscope/app/_service/_chat.py`：`extra_agent_middlewares(...)` 在装配阶段，`self._agent_cls(...)` 在其后 |
| workspace 路由不收敛路径 | `agentscope/app/_router/_workspace.py` 的 docstring 与 `backend.abspath(path, cwd=workspace.workdir)` |
| `abspath` 对绝对路径直接返回 | `agentscope/tool/_builtin/_backend.py::BackendBase.abspath` |
| 文件读取只靠明文 `X-User-ID` 或下载令牌 | `_router/_workspace.py::read_workspace_file` |
| `download_secret` 缺省时每进程随机生成 | `agentscope/app/_app.py`：`download_secret or secrets.token_urlsafe(32)` |
| 工具结果超限会落盘到 `sessions/` | `agentscope/workspace/_base.py` 的 offload 说明与 `agent` 构造的 `offloader=workspace` |
| `Toolkit.remove_tool` 能摘掉内置工具 | `Toolkit.__init__` 把 `tools` 归入 `basic` 组，`remove_tool` 遍历所有组 |
