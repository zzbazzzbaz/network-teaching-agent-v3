## 1. 概述

### 1.1 目标

在 `app/agent` 服务上一次性落地三件事，使学生侧具备"记得住、查得到、有自己空间"的完整体验：

| 能力 | 载体 | 一句话 |
|---|---|---|
| 工作区 | `LocalWorkspaceManager` | 每个 agent 一个本地目录，只用于工具结果落盘等多路复用场景 |
| 长期记忆 | `ReMeMiddleware` | 每个学生一个记忆库，跨会话记住画像、薄弱点、偏好 |
| 知识库 | `CollectionPerKbManager` + Qdrant | 学生个人库 + 全员只读公共库，支持 PDF/Word/PPT |

### 1.2 非目标

- 不做多租户下的容器级隔离（不引入 Docker / E2B / K8s）。
- 不做多副本部署与水平扩展（本期明确单进程）。
- 不实现自研 RAG 管道或记忆抽取逻辑，全部复用框架能力。
- **不实现主 API 与 agent 服务之间的代理层**（`app/api/*` 不在本期范围）。
- 不开放 agent 服务的 `/workspace` 文件浏览接口给学生。

### 1.3 全局约束（贯穿全篇）

1. **单进程部署**。ReMe 是进程内嵌（每个实例带文件监听与 23:00 cron）、workspace 缓存与下载密钥都是进程内状态，`uvicorn --workers > 1` 会导致重复索引与行为错乱。
2. **agent 服务不对外**，只接受主 API 带 `X-User-ID` 的内部转发（代理层由主 API 侧负责，本方案不实现）。
3. **`DATA_ROOT` 必须是绝对路径**，所有落盘子系统（workspace / memory / blobs）都从它派生。
4. **三个子系统共享同一个数据根，但生命周期完全不同**，禁止"整目录删除"式运维。
5. **`QDRANT_URL` 必填**，不做进程内 `path` 模式回退；缺失即启动失败。

## 2. 总体架构

### 2.1 拓扑

```
浏览器
  │ JWT
  ▼
主 API（app/main.py，对外唯一入口；本期不改造）
  │ 校验 JWT → 注入 X-User-ID
  ▼
Agent 服务（app/agent/main.py，create_app）
  ├── RedisStorage         DB1  会话 / agent / KB 元数据 / 凭据
  ├── RedisMessageBus      DB2  跨会话消息
  ├── LocalWorkspaceManager      <DATA_ROOT>/workspaces
  ├── ReMeMiddleware（按 user 缓存）<DATA_ROOT>/memory/reme
  ├── CollectionPerKbManager     Qdrant（服务端） + <DATA_ROOT>/blobs
  └── IndexWorker（进程内）
        │
        ├── PostgreSQL           用户 / 题目 / 作答（主 API 侧）
        ├── 腾讯云 COS           用户上传的图片等业务文件（主 API 侧）
        ├── 百炼 MaaS            LLM + Embedding
        └── Qdrant 服务          向量存储（必填，独立容器）
```

### 2.2 每轮对话的装配时序

1. 主 API 校验 JWT，把 `str(user.id)` 写进 `X-User-ID` 转发到 agent 服务（**外部前提，本方案不实现**）。
2. `get_current_user_id()` 读取该头；缺失/为空直接 401。
3. ChatService 解析 `(user_id, agent_id, session_id)` 对应的 workspace（缓存命中或创建，本地约 22ms）。
4. 调用 `extra_agent_middlewares(user_id, agent_id, session_id, workspace)`（**每轮一次**）：
   - 覆写 `workspace.instructions` 为教学精简版；
   - 按 `user_id` 取缓存中的 `ReMeMiddleware`（无则创建）；
   - 返回 `[ReMeMiddleware, MemoryOnlyToolsMiddleware]`。
5. `get_toolkit()` 汇总工具：workspace 内置工具 → 规划/团队/调度/后台 → 各中间件工具（`memory_search`）→ 知识库 `search_knowledge`。
6. 进入 `on_reply` 钩子，`MemoryOnlyToolsMiddleware` 剔除 shell / 文件 / 团队 / 调度类工具。
7. 构造 `Agent(offloader=workspace, middlewares=[...])`。
8. `reply_stream()`：模型推理 → 可能调用 `memory_search` / `search_knowledge` → 回复结束。
9. `ReMeMiddleware` 在回复后自动执行 `auto_memory` 写回记忆卡片。

### 2.3 组件职责边界

| 组件 | 负责 | 不负责 |
|---|---|---|
| 主 API（外部） | 鉴权、业务数据、COS、代理转发、路由白名单 | 不直接读写 `<DATA_ROOT>`；本期不改造 |
| workspace | 工具结果落盘、skills/MCP 分区（本期未用） | 不承载记忆与知识库数据 |
| ReMe | 记忆抽取、归并、检索 | 不感知业务题目数据 |
| 知识库 | 文档解析、切块、向量化、检索 | 不感知会话上下文 |
| 中间件工厂 | 三者唯一的装配入口 | 不持有请求级状态 |

## 3. 数据目录模型

### 3.1 缺陷与修正

当前 `.env` 中 `DATA_ROOT=./.data` 是**相对路径**，`config.py` 原样透传给 `LocalWorkspaceManager`，后者按**启动 cwd** 解析。用 systemd / docker / IDE / 命令行四种方式启动会落到四个不同目录。同时项目根下存在一个空的 `data/` 目录（无代码引用），与 `.data/` 并存。

**修正**：
- `DATA_ROOT` 在配置层统一转绝对路径；
- 目录名统一为 `.data/`（与现有 `.env`、`.gitignore` 一致），删除空的 `data/`；
- 移除未被任何代码使用的 `files_dir` 属性（文件上传走 COS）。

### 3.2 规范布局

```
<DATA_ROOT>/                          # 绝对路径，默认 <repo>/.data
├── workspaces/<agent_id>/            # LocalWorkspace（框架托管）
│   ├── sessions/<session_id>/        # 工具结果、上下文落盘
│   ├── skills/                       # 技能分区（本期未启用）
│   └── data/                         # 多模态文件（本期未启用）
│
├── memory/reme/<user_id>/            # ReMe vault（ReMe 自管, 首次使用时创建）
│   ├── daily/<date>/*.md             # 每日记忆卡片（agent 可读可改）
│   ├── digest/                       # dream 归并后的长期知识
│   ├── session/dialog/               # 会话转录
│   ├── resource/                     # 外部资源
│   ├── mem_session/                  # 记忆抽取过程会话
│   └── metadata/                     # 索引等持久状态
│
├── blobs/kb/<kb_id>/<doc_id>         # LocalBlobStore：知识库原件
└── blobs/kb/<kb_id>/<doc_id>         # LocalBlobStore：知识库原件
```

> 向量数据**不在** `DATA_ROOT` 下：`QDRANT_URL` 指向独立的 Qdrant 服务，其数据卷由该服务自行管理。

### 3.3 归属与生命周期

| 目录 | 写入方 | 隔离键 | 清理 | 备份 |
|---|---|---|---|---|
| `workspaces/<agent_id>` | 框架 | agent | **不清理**（TTL 只清内存缓存，磁盘常驻） | 否 |
| `memory/reme/<user_id>` | ReMe 自动写回 | 学生 | **不清理**（学生注销后仍保留） | **是** |
| `blobs/kb/<kb_id>` | LocalBlobStore | 知识库 | 删文档 / 删 KB 时由框架自动清理 | 是（可重建索引） |

> **本期不做级联清理**：删除 agent、学生注销都不会触发 `workspaces/` 与 `memory/` 的删除，这是已确认的决策（见 11.2），代价是磁盘只增与注销数据留存。
> `blobs/` 的自动清理来自框架自身行为（删文档/删库时触发），不属于我们实现的清理逻辑。

## 4. 配置项

### 4.1 新增 / 修改

| 配置项 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `DATA_ROOT` | str | 必填 | 绝对路径，配置层 `resolve()`；相对路径直接报错 |
| `QDRANT_URL` | str | 必填 | Qdrant 服务地址；**为空或缺失启动即失败，不做进程内 `path` 回退** |

复用现有：`LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL`（ReMe 的抽取模型与主模型同一套）。

以下**不设配置项，直接硬编码**：

| 常量 | 取值 | 位置 |
|---|---|---|
| 公共库归属账号 | `"system"` | `app/agent/access.py` |
| 公共库 id 列表 | 代码内常量（换库需发版） | `app/agent/access.py` |
| 记忆抽取模型 | 复用主模型 `qwen3.8-flash`（`LLM_MODEL`） | `app/agent/memory.py` |
| 记忆开关 | 恒开启（回滚靠回退代码，不做运行时开关） | `app/agent/middlewares.py` |
| 工具剔除清单 | 含团队 / 调度 / `Task*`，固定不变 | `app/agent/middlewares.py` |

> 校验分两层：
> 1. **格式**：`Settings` 加载时校验 `QDRANT_URL` 非空且为 `http(s)://`，不合法直接抛配置错误。
> 2. **连通性**：`QdrantStore` 的 client 是**懒创建**的，构造不会连网；因此必须在 lifespan 启动阶段显式探活（见 5.6），否则错误会拖到首次检索才暴露。

### 4.2 派生路径（`Settings` property）

```python
@property
def data_root(self) -> Path: ...          # 绝对路径

@property
def workspaces_dir(self) -> Path: ...     # data_root / "workspaces"

@property
def memory_dir(self) -> Path: ...         # data_root / "memory" / "reme"

@property
def kb_blobs_dir(self) -> Path: ...       # data_root / "blobs"
```

### 5.2 `app/agent/workspace.py`

```python
TEACHING_WORKSPACE_INSTRUCTIONS = (
    "<workspace>\n"
    "你拥有一个属于当前学生的工作目录, 由系统自动维护。\n"
    "你不直接读写其中的文件, 也不需要创建目录或项目。\n"
    "</workspace>"
)

def build_workspace_manager(settings) -> LocalWorkspaceManager:
    return LocalWorkspaceManager(
        str(settings.workspaces_dir),
        isolation=IsolationPolicy.PER_AGENT,
        ttl=3600.0,
    )
```

要点：
- `instructions` 不含占位符（构造后赋值不会再格式化）。
- 不要选 `PER_USER`：本地 workspace 的 workdir 恒按 `agent_id` 拼接，与 `PER_USER` 的缓存键不一致。

### 5.3 `app/agent/memory.py`

```python
_CACHE: dict[str, ReMeMiddleware] = {}

def build_chat_model(settings) -> OpenAIChatModel: ...

async def get_memory(settings, user_id: str) -> ReMeMiddleware:
    mw = _CACHE.get(user_id)
    if mw is None:
        mw = ReMeMiddleware(
            workspace_dir=str(settings.memory_dir / user_id),
            parameters=ReMeMiddleware.Parameters(
                chat_model=build_chat_model(settings),
                mode="agent_control",
                top_k=5,
            ),
        )
        _CACHE[user_id] = mw
    return mw

async def close_all() -> None:
    for mw in _CACHE.values():
        await mw.close()
    _CACHE.clear()
```

要点：
- **按 `user_id` 缓存**，禁止每轮新建（否则每轮泄漏一个文件监听 + 一个 23:00 cron）。
- `mode="agent_control"`：只暴露 `memory_search`，检索按需发生。
- `chat_model` 复用主模型：用 `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL`（`qwen3.8-flash`）构造 `OpenAIChatModel`，不单独配轻量模型。
- 不传 `embedding_model`：走 bm25，零 embedding 成本。
- vault 子目录由 ReMe 自行创建：`daily/<date>/*.md`、`digest/`、`session/dialog/`、`resource/`、`mem_session/`、`metadata/`（`reme-ai==0.4.2.1`）。
- 关闭时机：见 5.6。

### 5.4 `app/agent/middlewares.py`

```python
_STRIP_TOOLS = [
    "Bash", "PowerShell", "Edit", "Glob", "Grep", "Read", "Write",
    "TeamCreate", "AgentCreate", "AgentInvite", "TeamDelete", "TeamSay",
    "ScheduleCreate", "ScheduleView", "ScheduleList", "ScheduleDelete",
    "TaskCreate", "TaskGet", "TaskList", "TaskUpdate",
]

class MemoryOnlyToolsMiddleware(MiddlewareBase):
    async def on_reply(self, agent, input_kwargs, next_handler):
        await agent.toolkit.remove_tool(_STRIP_TOOLS)
        async for item in next_handler(**input_kwargs):
            yield item

async def agent_middlewares(user_id, agent_id, session_id, workspace):
    settings = get_settings()
    workspace.instructions = TEACHING_WORKSPACE_INSTRUCTIONS
    return [
        await get_memory(settings, user_id),
        MemoryOnlyToolsMiddleware(),
    ]
```

> **为什么必须剔除团队与调度工具**：服务层对非 worker 角色**无条件**下发 `TeamCreate` / `AgentCreate` / `AgentInvite` / `TeamSay` / `TeamDelete`。学生一句"帮我建个 agent"就能创建子 agent 并持续消耗 token；调度工具同理能创建定时任务。这两组必须显式摘掉。

### 5.5 `app/agent/knowledge.py` 与 `app/agent/access.py`

职责分离：知识库模块只负责"怎么存/怎么查"，访问策略单独成模块——`ResourceAccessPolicyBase` 管的是 `CREDENTIAL` / `AGENT` / `KNOWLEDGE_BASE` 三类跨 owner 资源的授权，不属于知识库。

```python
# knowledge.py —— 只做知识库装配
def build_vector_store(settings) -> QdrantStore:
    return QdrantStore(url=settings.qdrant_url)          # 无 path 回退

def build_blob_store(settings) -> LocalBlobStore: ...
def build_parsers() -> list: ...                        # Text/PDF/Word/PPT
def build_kb_manager(settings, storage) -> CollectionPerKbManager: ...


# access.py —— 只做跨 owner 授权
PUBLIC_OWNER = "system"
PUBLIC_KB_IDS: tuple[str, ...] = ()

class TeachingAccessPolicy(ResourceAccessPolicyBase): ...
def build_access_policy() -> TeachingAccessPolicy: ...
```

要点（细节见知识库决策文档）：
- `QDRANT_URL` 必填；`QdrantStore` 的 client 懒创建，**不做隐式连接**——连通性由启动探活负责（见 5.6）；
- `CollectionPerKbManager` 一人一 collection；
- `LocalBlobStore` 必须传绝对路径；
- 公共库通过 `ResourceRef(permission=READ)` 授权，**不得给 EDIT**（在 `access.py` 中定义）；
- embedding 凭据必须与 KB 同 owner，用户注册时在主 API 侧触发创建。

### 5.6 `app/agent/main.py` 与 `app/agent/lifespan.py`

`main.py` 只做装配：

```python
def create_agent_app() -> FastAPI:
    settings = get_settings()
    storage = RedisStorage(...)
    app = create_app(
        storage=storage,
        message_bus=RedisMessageBus(...),
        workspace_manager=build_workspace_manager(settings),
        knowledge_base_manager=build_kb_manager(settings, storage),
        knowledge_parsers=build_parsers(),
        blob_store=build_blob_store(settings),
        resource_access_policy=build_access_policy(),
        extra_agent_middlewares=agent_middlewares,
        enable_index_worker=True,          # 改为 True
        enable_scheduler=False,
        enable_channel_worker=False,
        title="计算机网络教学智能体 Agent",
        version="0.1.0",
    )
    wrap_lifespan(app, settings)           # 启动探活 + 退出时 close_all
    return app
```

`create_app` 自己管理 lifespan 且不暴露钩子，包装逻辑独立在 `lifespan.py`：

```python
def wrap_lifespan(app: FastAPI, settings: Settings) -> None:
    original = app.router.lifespan_context

    @asynccontextmanager
    async def lifespan(app: FastAPI) -> AsyncGenerator[Any]:
        async with original(app) as state:
            try:
                await verify_qdrant(settings.qdrant_url)   # 连不上直接起不来
                yield state
            finally:
                await close_all()

    app.router.lifespan_context = lifespan
```

`verify_qdrant` 放在 `knowledge.py`：

```python
async def verify_qdrant(url: str) -> None:
    """启动探活：QdrantStore 的 client 懒创建, 必须显式打一次。"""
    client = QdrantStore(url=url).get_client()
    try:
        await client.get_collections()
    finally:
        await client.close()
```

## 6. 关键契约

### 6.1 身份传递

- 唯一来源：请求头 `X-User-ID`，明文，无签名。
- 主 API 是唯一合法调用方；agent 端口只监听内网 / localhost。
- ID 类型统一 `str(uuid)`。
- 记忆隔离、知识库归属、workspace 路由全部依赖它——**一旦多人共用一个 ID，三类数据会全部串在一起**，且线上极难发现。主 API 侧必须加断言：`X-User-ID` 必须来自已校验的 JWT subject，不允许客户端直接传。

### 6.2 路由暴露面（主 API 侧交付要求，本期不实现）

本方案**不新建代理层**（不新增 `app/api/*` 文件）。下表是对主 API 侧的交付要求，由现有入口按其既有方式实现；本方案只负责"agent 服务不对外暴露"这一侧，验收时按 9.1 场景 8 实测确认。

| 路由前缀 | 是否转发 | 说明 |
|---|---|---|
| `/chat` | ✅ | 对话主链路 |
| `/sessions` | ✅ | 会话管理 |
| `/agent` | ✅ | agent 配置 |
| `/knowledge_bases` | ✅ | 知识库增删查与检索 |
| `/credential` | ✅ | 注册时创建 embedding 凭据 |
| `/model`、`/embedding-model` | ✅ | 可选模型列表 |
| `/health` | ✅ | 探活（仅内网） |
| `/workspace/*` | ❌ | **任意路径读宿主机文件**，见 6.3 |
| `/mcp`、`/skill`、`/hub` | ❌ | 本期不使用 |
| `/schedule`、`/sop`、`/realtime`、`/channels`、`/tts-model` | ❌ | 本期不使用 |

### 6.3 安全红线：`/workspace` 路由

框架源码明确不做路径收敛：

> Paths are not confined to the workspace root: for a sandboxed backend the reachable filesystem is the sandbox, and for a local one **the caller is already trusted with the host**.

`GET /workspace/files?path=/etc/passwd` 会直接流式返回宿主机文件。若主 API 原样转发，任何登录学生可读取 `app/.env`（LLM key、DB 密码、JWT secret）、其他学生 workspace、Redis 落盘数据。

**约束**：
- 主 API 侧按 6.2 的前缀白名单放行，不转发 `/workspace/*`；
- 若将来确需文件浏览，必须在代理层做 `realpath` 前缀校验，或改用独立上传接口。

### 6.4 会话配置

- 建会话时通过 `SessionConfig.knowledge_config.knowledge_base_ids` 挂载「个人库 + 公共库」；

- 记忆无需会话级配置，按 `user_id` 全局生效。

## 7. 依赖变更

```bash
uv add "agentscope[service,storage-redis,vdb-qdrant]==2.0.11"
uv add "agentscope[memory-reme]==2.0.11"
uv add python-docx python-pptx
```

| 变更 | 影响 |
|---|---|
| `vdb-qdrant` | 引入 `qdrant-client`（含 `grpcio` / `protobuf`），已验证与 COS SDK 无冲突 |
| `memory-reme` | 引入 `reme-ai` 等共 28 个包（含 `fastmcp`、`loguru`、`authlib`） |
| `python-docx` / `python-pptx` | Word / PPT 解析；PDF 的 `pypdf` 已在 core 依赖内 |

> **`reme-ai` 必须钉 `0.4.1.11`**：AgentScope 2.0.11 的嵌入配置引用了 `dream_extract_step` / `dream_integrate_step` / `dream_topics_step` / `dream_finish_step`，而 `reme-ai>=0.4.1.12` 已移除 `dream_topics_step`，装最新版会在 `start()` 时抛 `Unregistered backend 'dream_topics_step'`。`0.4.1.11` 是实测可用的最新版本。

**不要**用 `agentscope[rag]`（会带 `pandas` / `xlrd` / `openpyxl`）。

### 7.1 部署变更

Qdrant 成为**必填常驻服务**，已在 `docker-compose.yml` 新增（`v1.20.0`）：

```yaml
qdrant:
  image: qdrant/qdrant:v1.20.0
  container_name: teaching-qdrant
  ports:
    - "127.0.0.1:6333:6333"
  volumes:
    - qdrantdata:/qdrant/storage
  restart: unless-stopped
```

> 健康检查命令取决于镜像内可用的工具（`curl` / `wget` / `bash` 未必存在），落地时按实际情况补 `healthcheck`；无论是否配置，agent 侧的启动探活（5.6）都是最终保证。

`.env` 新增：

```
QDRANT_URL=http://127.0.0.1:6333
```

要求：agent 服务启动前 Qdrant 必须就绪；配置格式由 4.1 校验，连通性由 5.6 的启动探活兜底，任一不满足进程都起不来。

## 9. 测试与验收

### 9.1 端到端场景

| # | 场景 | 期望 |
|---|---|---|
| 1 | 学生 A 首次对话，提到"我在准备期末，网络层最弱" | 回复结束，`memory/reme/<A>/` 出现卡片 |
| 2 | A 新开会话问"我哪块最弱" | 命中记忆，回答网络层 |
| 3 | 学生 B 问同样问题 | 不出现 A 的信息 |
| 4 | 连续 10 轮对话 | 活跃 ReMe 实例恒为 1 |
| 5 | A 上传 PDF 建个人库并挂载提问 | 索引 `ready`，检索命中 |
| 6 | B 用相同问题检索 | 检索不到 A 的内容 |
| 7 | 普通用户请求公共库删除接口 | 403 |
| 8 | 请求 `/workspace/files?path=/etc/passwd`（主 API 侧前置条件，非本方案实现） | 404/403 |
| 9 | 学生侧工具清单 | 无 `Bash`/`Write`/`Read`/`TeamCreate`/`AgentCreate`/`Schedule*` |
| 10 | 系统提示检查 | 不含 Bash / git / uv / README 等内容 |
| 11 | 服务重启 | 记忆与知识库检索结果保持；同一 agent 的 workspace 目录复用 |
| 12 | 部署检查：uvicorn worker 数 = 1 | 部署脚本与文档固定单 worker；不得出现 2 个 ReMe 监听同一 vault |
| 13 | 缺失或不可达的 `QDRANT_URL` 启动 | 进程启动即失败，日志明确指向 Qdrant，不进入服务状态 |

### 9.2 指标

| 指标 | 目标 |
|---|---|
| workspace 初始化 | < 100ms（本地实测 22ms） |
| 首轮对话额外延迟（记忆未命中） | < 300ms |
| `memory_search` 延迟 | < 500ms（bm25，本地） |
| 单学生内存增量（ReMe 实例） | 需实测并记录基线 |
| 磁盘增长 | `workspaces/`、`memory/`、`blobs/` 均只增不清理，需设置容量告警与上限 |

### 9.3 回滚

- 记忆：回退代码（工厂不再返回 ReMe 中间件），历史数据保留；不设运行时开关。
- 知识库：`enable_index_worker=False` + 不下发 `knowledge_base_ids`，路由可继续挂着。
- 工作区：回退到仅 `create_app` 默认参数（不改动数据目录）。

## 10. 风险与缓解

| # | 风险 | 等级 | 缓解 |
|---|---|---|---|
| 1 | `/workspace` 路由可读宿主机任意文件 | **高** | 由主 API 侧按 6.2 白名单拦截（不在本方案实现）；本方案确保 agent 端口不对外 |
| 2 | `X-User-ID` 可伪造 / 多人共用 | **高** | 仅内网；主 API 从 JWT 派生（外部前提），禁止透传客户端值；上线前加断言 |
| 3 | 多 worker / 多副本不成立 | **高** | 部署固定单 worker；多副本前需把 ReMe 外部化（共享 vault + 索引一致性） |
| 4 | ReMe 实例无界增长 | 中 | 按 `user_id` 缓存 + 上限/LRU + 退出时 `close_all` |
| 5 | 每轮 `auto_memory` 抽取成本 | 中 | 上线后实测 token/耗时；必要时降频或换轻量模型 |
| 6 | dream 集中触发（23:00 × 用户数） | 中 | 控制规模；规模化前改离线批处理 |
| 7 | ReMe 默认开启文件日志 | 低 | 日志落在进程 cwd 的 `logs/`（`log_to_file` 默认 True，AgentScope 的嵌入配置未覆盖）；需纳入 gitignore 与轮转策略 |
| 8 | 剔除 `Read` 导致 offloader 兜底失效 | 中 | 业务工具单次结果 < 20k；必要时保留 `Read`（需评估读宿主风险） |
| 9 | ~~embedding 端点未验证~~ **已验证** | — | 用现有 `LLM_API_KEY` 直连 DashScope `text-embedding-v4` 返回 200 / 1024 维，无需单独申请 key |
| 10 | ~~ReMe 未在 Python 3.14 实跑~~ **已验证** | — | `reme-ai==0.4.1.11` 在 3.14 下启动 124ms，记忆写入与检索均通过 |
| 11 | Qdrant 服务可用性（新增常驻依赖） | 中 | compose 健康检查 + lifespan 启动探活（`get_collections`），连不上直接起不来 |
| 12 | `instructions` 覆写依赖装配时序 | 低 | 升级 AgentScope 时复核 `_chat.py` 调用顺序 |
| 13 | 磁盘只增（`workspaces/`、`memory/` 不清理） | 中 | 纳入容量告警；确需清理时按子目录手工处理，不做自动化 |
| 14 | 公共库权限误配成 EDIT | 低 | policy 写死 READ + 单测断言 |
| 15 | 注销后数据留存 | 中 | 本期既定决策（不清理）；需在隐私政策中说明留存范围与删除申请流程 |
